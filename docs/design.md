# デザイン方針 — UI/UX刷新ガイド

作成日: 2026-08-16
上位方針: [rebuild-plan.md](./rebuild-plan.md) §3

対象読者: このサイトのテンプレート（`app/templates/`）・CSS（`app/static/css/app.css`）・JS（`app/static/js/app.js`）を触る人。個々のPR前に「この画面はこの原則に沿っているか」を確認する用途。

---

## 1. デザイン原則

1. **迷わせない、選ばせすぎない** — 現状は検索クエリ構文（`avatar:` `tag:` `free:true` など）がパワーユーザー向けに強く、初見ユーザーの主導線になっていない。**主導線は「クリックだけで絞り込めるUI」**（目的タイル・チップ・チェックボックス）とし、クエリ構文は「上級者向けオプション」として折りたたむ。
2. **既存のApple HIGトークンを土台として継続する**（下記§2）。ライト/ダーク両対応、`--radius-*` によるカード基調のUIは維持したまま、情報設計とコンポーネントの追加で刷新する。ゼロから作り直さない。
3. **「見逃さない」を視覚的に一番目立たせる** — お気に入り・監視・通知は差別化の核（[rebuild-plan.md](./rebuild-plan.md) §2.3）。ボタンやバッジのプライオリティを検索結果カードの中で最上位に置く。
4. **1カードで意思決定が完結する** — 商品カードは「対応アバター」「価格（セール表示込み）」「Quest対応」「無料/ツール」バッジ「お気に入り」ボタンが一目で揃うこと。詳細ページに行かずに一覧で判断できる状態を保つ。
5. **参加できることを可視化する** — 「このアバターを追加リクエスト」「素体グルーピングを提案」など、ユーザー参加型の導線（[rebuild-plan.md](./rebuild-plan.md) §2.3, §6.2）は隠さず、該当ページの目立つ位置に常設する。

---

## 2. デザイントークン（現状を継続・拡張）

`app/static/css/app.css` の `:root` にApple system-color相当のトークンが既に定義済み（`--bg` `--surface` `--text` `--muted` `--brand` `--sale` `--free` `--tool` `--quest` など、ライト/ダーク自動切替＋手動トグル対応）。これは変更せず土台として使う。

### 2.1 追加が必要なトークン

| トークン | 用途 | 備考 |
|---|---|---|
| `--trending` | 急上昇ランキング用アクセント色（既存の`--sale`等と衝突しない色） | オレンジ系(`#ff9500` / dark `#ff9f0a`)を想定。SF Symbolsの`flame`相当の温度感 |
| `--request` | ユーザー参加型導線（追加リクエスト、提案ボタン）の色 | 既存の`--brand`とは別トーンにし「運営機能ではなくコミュニティ機能」と視覚的に区別する |
| `--quest-badge-bg` / `--tool-badge-bg` 等 | 既存の`--quest`/`--tool`をバッジ背景として使う際の低彩度版 | 現状バッジ色の扱いをコンポーネント側で個別実装している箇所があれば統一する |

### 2.2 タイポグラフィ・アイコン

- 現状San Francisco相当のシステムフォントに準拠（明記された`font-family`宣言があれば継続）。絵文字（🔥📈🆕）を競合2社とも多用しているが、本サイトはHIG的な統一感を保つため**絵文字よりアイコン（SVG）を優先**し、色トークンで意味を伝える（例: 急上昇=`--trending`色の矢印アイコン）。
- バッジ文言は「SALE」「無料」「Quest対応」「ツール」など既存の日本語/英語混在を維持しつつ、新設する「急上昇」「NEW」「みんなの推薦」等も同じトーンで統一する。

## 3. 情報設計（サイト全体）

### 3.1 グローバルナビゲーション（現状 `base.html`）

現状: `検索 / アバター / 素体 / セール / 無料 / ツール / Me / Login`

変更方針:
- 「素体」はコアユーザー以外に意味が伝わりにくい用語のため、ナビゲーション直下ではなくアバター詳細ページからの導線に格下げしてよい（完全に消さない。URLとSEO価値は維持）。
- 「目的から探す」（Quest対応／MA対応／無料／セール中）をグローバルナビまたはトップページ最上部に新設し、検索クエリを知らないユーザーの主要な入口にする（[rebuild-plan.md](./rebuild-plan.md) §6.2）。
- ハンバーガー化はせず、既存のフラットなナビ構造を維持（モバイルでは横スクロール or 折りたたみのいずれかをコンポーネント実装時に検証）。

### 3.2 トップページ構成（優先順位案、上から順）

1. **価値訴求ヒーロー**（Phase2で実装済み）— キャッチコピーは「見逃さない」を軸に更新を検討。
2. **目的から探すタイル**（新設） — Quest対応 / MA対応 / 無料で揃える / セール中 / 急上昇（新設）。
3. **急上昇ランキング**（新設、1日/7日/30日切替）— [rebuild-plan.md](./rebuild-plan.md) §2.3の通知連携ともつながる目玉機能。
4. **新着**（既存を継続）
5. **注目アバター**（既存を継続、素体グループのバッジを追加検討）
6. **セール／無料のハイライト**（既存 `sales.html` `free.html` への導線として要約表示、継続）
7. **「このアバターも追加してほしい」導線**（新設、フッター付近 or サイドバー） — [rebuild-plan.md](./rebuild-plan.md) §2.3

### 3.3 新設ページ

- `/tags/{slug}` — 独自ファセットタグ（テイスト/体型/カラー等）のランディングページ（[rebuild-plan.md](./rebuild-plan.md) §6.6）。一覧ページ（`items/list.html`）のレイアウトを再利用しつつ、タグの説明文・関連タグ・SEO用meta descriptionを追加する。
- `/requests`（仮）— ユーザーからの追加リクエスト一覧・投稿フォーム・ステータス（審査中/反映済み）。
- `/ranking`（仮、または既存ランキング機能の拡張）— 急上昇ランキングの全量表示、期間切替。

## 4. 画面別の変更方針

### 4.1 検索ページ (`app/templates/items/list.html`, `sort_bar.html`)

- 現状: クエリ構文入力補助＋AND検索＋並び替え＋人気タグクラウド（すべてPhase1/3で実装済み）。
- 変更: クエリ入力欄の**上**に、チェックボックス/チップ形式の絞り込み（Quest対応・無料・セール・ツール・NSFW除外）を常設し、これらの操作がクエリ構文へ自動変換される見た目にする（内部実装は既存のクエリパーサをそのまま使える設計が望ましい）。
- 人気タグクラウドは既存のBOOTHセラータグ集計に加えて、新設する独自ファセットタグ（テイスト等）を別セクションとして分離表示する。

### 4.2 商品カード (`items/item_cards.html`, `favorite_button.html`)

- バッジの優先順位を明確化: 「急上昇」＞「NEW」＞「SALE」＞「Quest対応」＞「無料/ツール」の順で、同時に複数該当する場合は最大2〜3個に絞る（現状バッジが増えすぎるとカードが煩雑になるため、既存実装のバッジ数を一度棚卸しして整理する）。
- お気に入りボタンの視認性を上げる（現状HTMX部分更新で実装済み、位置・サイズの調整のみ）。

### 4.3 商品詳細 (`items/list.html`関連, item詳細テンプレート)

- 対応アバター一覧・関連商品（既存8件）に加え、「このアバターと同じ素体の兄弟アバター」への導線を強調（既存データはあるので表示強化のみ）。
- SEO用の動的title/OGP/JSON-LD（[rebuild-plan.md](./rebuild-plan.md) §4.3-4.5）をこのページから優先実装。
- ショップ監視・お気に入りボタンをファーストビュー内に配置。

### 4.4 アバター詳細 (`avatars/list.html`, `base_bodies/detail.html`)

- 「対応商品」のカテゴリ別件数表示（既存）を目的タイル（Quest対応のみ表示等）でフィルタ可能にする。
- 素体グルーピングの「提案する」ボタンを新設（[rebuild-plan.md](./rebuild-plan.md) §6.5）。

### 4.5 マイページ (`app/templates/`配下、`/me`)

- 通知設定UIを「チャンネル（Web Push/Discord/Misskey）× 種類（新着/セール/価格変動/急上昇）」のマトリクスとして再設計し、ユーザーが自分で組み合わせを選べることを視覚的に伝える。
- BOOTHライブラリ手動貼り付けインポートのUIは撤去し、「お気に入りアバター登録」への導線に一本化（[rebuild-plan.md](./rebuild-plan.md) §1.2）。

### 4.6 新規: 追加リクエスト画面

- フォームは最小限（BOOTHの商品URL or ショップURL or キーワードを貼るだけ）。
- 投稿後のステータス（審査中/クロール成功/反映済み/対象外）が本人に見える設計とし、通知（既存Web Push基盤を流用）で反映を知らせる。

## 5. コンポーネント指針

| コンポーネント | 方針 |
|---|---|
| 目的タイル | アイコン＋短いラベル＋該当件数（例: 「Quest対応 1,204件」）。既存ブールフラグをそのまま件数集計に使えるため実装コストは低い |
| 急上昇ランキングカード | 順位・アイテム名・対応アバター・増分（例: 「+237 (24h)」）。よりみち型の「差分の伸び」表現を踏襲しつつ、色は`--trending`トークンで統一 |
| 追加リクエストボタン/バッジ | `--request`トークンで運営機能と視覚的に区別。「あなたの一言がサイトを育てます」等、参加を促すマイクロコピーを添える |
| バッジ群 | 1カードあたり最大3個、優先順位は§4.2の通り。アイコン化を優先 |
| タグチップ | 独自ファセットタグとBOOTHセラータグを色または枠線スタイルで区別（例: 独自タグは塗りつぶし、セラータグは枠線のみ） |

## 6. レスポンシブ・アクセシビリティ

- 既存トークンはダーク/ライト自動追従＋手動トグル対応済み。新設コンポーネントもこの2系統（`@media (prefers-color-scheme: dark)` と `[data-theme="dark"]`）両方に対応させる。
- 目的タイル・急上昇ランキングはモバイルで横スクロールカルーセルにする（既存の無限スクロール実装と衝突しないよう、独立したスクロールコンテナにする）。
- コントラスト比はHIGの`--muted`/`--muted-2`基準を踏襲し、新トークン（`--trending`/`--request`）もWCAG AA相当のコントラストを確保する。

## 7. 実装上の注意

- 現行は Bootstrap 5（CDN、CSSのみ）をHIGトークンで上書きする構成（`app.css` 冒頭コメント参照）。この構成は変更せず、新規コンポーネントも「Bootstrapの素の見た目 → app.cssで上書き」の流儀を踏襲する。フレームワークの入れ替え（Tailwind化など）は本刷新のスコープ外とする。
- HTMXの部分更新パターン（`hx-trigger="revealed"`など）は継続。新設の急上昇ランキング・追加リクエストフォームもHTMXでの部分更新を基本とする（SPA化はしない）。
- 新規テンプレートを追加する際は、既存の `items/item_cards.html` 等の部分テンプレートを再利用し、重複実装を避ける。
